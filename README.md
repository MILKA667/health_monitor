# HealthMonitor

Платформа удалённого наблюдения за пациентами с сахарным диабетом, артериальной гипертонией и бронхиальной астмой.
Учебный MVP для четырёх ролей: врач, пациент, родственник, администратор.

Платформа **не ставит диагноз** и не даёт пациенту рекомендаций от своего имени. Персональные и медицинские данные
обрабатываются на серверах в РФ (152-ФЗ). Каждое действие с медданными пишется в неизменяемый журнал аудита,
измерения удалить нельзя.

## Структура

| Каталог | Что внутри |
|---|---|
| `frontend/` | React 19, Vite 8, react-router 7. В dev-режиме `/api` проксируется на Flask |
| `backend/` | Flask + PostgreSQL: вход и заявки, медкарта, алерты, пороги, отчёты, экраны пациента и родственника, админка |
| `healthmonitor-design/` | Пакет дизайна v2: спецификация (`SPEC.md`), макеты страниц и интерактивные прототипы |
| `deploy/` | Docker Compose (PostgreSQL + gunicorn + nginx) и инструкция по выкатке |

## Быстрый старт

Нужны PostgreSQL 16+ и Python 3.13+.

```powershell
cd backend
python -m venv venv
venv\Scripts\pip install -r requirments.txt
copy .env.example .env          # заполнить DB_PASSWORD и SECRET_KEY
venv\Scripts\flask --app app init-db
venv\Scripts\flask --app app seed-demo
venv\Scripts\python app.py      # http://localhost:5000
```

```powershell
cd frontend
npm ci
npm run dev                     # http://localhost:5173
```

`init-db` и `seed-demo` можно запускать повторно — данные не дублируются.

## Что реализовано

**Вход и доступ:** вход по телефону или e-mail, заявка на доступ с согласиями, восстановление пароля по коду,
первый вход пациента с заменой временного пароля и согласиями.

**Врач:** рабочий список с группами по критичности, медкарта (показатели с графиком, назначения и приверженность,
переписка, журнал алертов), алерты с эскалацией дежурному, пороги и уведомления на пациента или шаблоном
на нозологию, сообщения с непрочитанными, отчёты трёх типов с печатной версией в PDF.

**Пациент:** главная с планом на сегодня, ввод показателя с проверкой диапазона, экран критического алерта
с памяткой врача, история измерений с графиком, напоминания о лекарствах и замерах, чат с врачом, профиль
(близкий, устройства, каналы, согласия), подключение и синхронизация устройства, смена пароля.

**Родственник:** показатели и алерты близкого с хронологией реакции врача, SMS при критичном значении,
без доступа к переписке.

**Администратор:** заявки (одобрение с картой пациента, доступом родственника или данными врача,
отклонение и отмена решения), пользователи с поиском, блокировкой, сбросом пароля и удалением аккаунта,
журнал аудита с группами событий.

Управление учётными записями: пароли хранятся только хэшами, поэтому «посмотреть» пароль нельзя —
администратор может выдать новый временный (он показывается один раз и уходит SMS, старые сеансы
завершаются). Удаление аккаунта блокирует вход, очищает имя и контакты; медицинские данные и журнал
аудита сохраняются.

## Тесты

```powershell
cd backend
venv\Scripts\pip install -r requirements-dev.txt
venv\Scripts\python -m pytest

cd ..\frontend
npm run lint
npm test
npm run build
```

Тесты бэкенда идут на отдельной базе `health_monitor_test` (имя меняется через `TEST_DB_NAME`) и очищают её
перед каждым тестом — рабочие данные не затрагиваются.

## Логика алертов

| Уровень | Когда | Что происходит |
|---|---|---|
| Критично | значение за критическим порогом | алерт врачу сразу, SMS родственнику при согласии; без реакции 15 минут — эскалация дежурному врачу |
| Внимание | вне цели, но до критического порога | алерт врачу без эскалации |
| Нет данных | нет измерений 2 дня | отдельный алерт врачу |

Пороги по умолчанию: глюкоза — критично ниже 3,9 и выше 13,9 ммоль/л, цель 4,4–10,0; верхнее давление —
критично ниже 90 и выше 160, цель 100–140; нижнее — внимание выше 90, критично выше 100; ПСВ — критично ниже 50%
от лучшего результата, внимание ниже 80%. Пороги настраиваются на пациента или шаблоном на нозологию.

Деплой — см. [`deploy/README.md`](deploy/README.md).
