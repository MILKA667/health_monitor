# HealthMonitor — пакет дизайна для разработки (v2)

Все экраны MVP в стиле v2 (22 страницы + 20 состояний): врач, пациент, родственник, администратор, вход, заявка на доступ, восстановление и смена пароля, первый вход пациента.

## Что внутри
- `SPEC.md` — главный документ: правила из устава, логика алертов, карта страниц с маршрутами и поведением, компоненты.
- `tokens.css` — цвета, типографика, отступы, радиусы, размеры контролов.
- `pages/` — статичные HTML-снимки всех страниц. Начните с `pages/index.html`.
- `pages/states/` — дополнительные состояния: вкладки медкарты, принятый алерт, ошибки в формах, шаги заявки, восстановления пароля и первого входа, вкладки админки.
- `pages/Rules.html` — лист правил интерфейса.
- `prototype-source/` — исходники интерактивных прототипов. Разметка — HTML с подстановками `{{…}}`, циклами `<sc-for>` и условиями `<sc-if>`; поведение — класс `Component`, метод `renderVals()`. Это референс состояний и правил, а не код для копирования.

## Как передать в разработку
Положите папку в репозиторий (например, в `design/`) и поставьте задачу, указав свой стек:

> Реализуй фронтенд HealthMonitor по `design/SPEC.md`. Внешний вид бери из `design/pages/*.html` и `design/pages/states/*.html`, состояния и поведение — из `design/prototype-source/*.dc.html`. Токены из `design/tokens.css` перенеси в тему проекта, цвета и размеры не хардкодь. Стек: [ваш стек]. Сначала сделай общие компоненты из раздела 3 SPEC, затем страницы по ролям. Данные пока моковые, через слой API, который потом подключим к бэкенду. Сохрани доступность: настоящие кнопки и поля с label, видимый фокус, зоны нажатия 44 px на мобильных.

Лучше давать по одной роли за задачу:
1. Вход, заявка, восстановление пароля, первый вход и общие компоненты.
2. Врач.
3. Пациент и родственник.
4. Администратор.
